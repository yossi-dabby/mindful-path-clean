# שלב 0 של השלמת סדרות הטפסים בעברית

🟢 חבילת מיפוי ומפרטים לסקירה. אין בחבילה שינוי בקוד האפליקציה, בקטלוג הפעיל או בטופסי PDF. ההכנה ההנדסית הושלמה; שלב 0 עדיין פתוח להכרעות מקצועיות, זכויות והקפאת מניפסט.

הבסיס הוא main לאחר PR 17, commit `f698e7bc47bef5329d2bfe066f48a311549c40f6`, וקטלוג `0.6-p4-02`. [תוכנית ההשלמה המוצעת](https://chatgpt.com/space/page_02494d140b7c81919bc157e6f46862e6) היא מקור ההיקף החדש. המספרים אינם מכסה שנקבעה בתוכנית המקורית ואינם מספר מפגשי טיפול. אימות האתר החי נמסר בידי בעל הפרויקט; בחבילה זו נערכה בדיקה מקומית, לא בדיקת ייצור חדשה.

## מה נבדק ומה הוכן

| פריט | תוצאה |
| --- | --- |

כל 135 טופסי ההרחבה עדיין מסומנים במקור ללא אישור גיל וללא אישור שחרור. אין הסקה ממיזוג, בדיקות או צפייה באתר לכך שהתוכן אושר מקצועית. OCD-01 ו־TRAUMA-01 ממופים במפורש כהכנה לפגישה, ולא ככיסוי של ERP או עיבוד טראומה.

## ממצא הנדסי מרכזי

הקטלוג הנוכחי הוא 133,980 בתים בתעבורת JSON קומפקטי. תחזית לפי המבנה הקיים וכותרות היחידות המוצעות מגיעה ל־451,351 בתים ב־970 טפסים, מתחת לחסם הקיים של 524,288 בתים. נותר מרווח של 72,937 בתים בלבד. תרחיש כותרות ארוכות יותר מגיע ל־560,311 בתים ועובר את החסם. לכן אין צורך מוכח לשנות ארכיטקטורה כעת, אך נדרשת מדידה של כל קטלוג סופי לפני שחרור; אסור להניח שספירת קבצים לבדה מבטיחה התאמה.

משקל ה־PDF הסופי מוערך ב־22.4 MB לפי גודל הקבצים הקיימים, לפני תוספת אפשרית של חומרי מלווים. זו תחזית אחסון של הקבצים בלבד, ולא מדידת זיכרון או ביצועים בשרת.

## סדר העבודה הבא

1. בעל הפרויקט ממנה סוקרים לתחומים ולגילים, ובודק זכויות; אפשר שאותו אדם ימלא כמה תפקידים לפי הכשרתו.
2. הסוקרים בוחרים ומעמידים לבדיקה את המדריכים המלאים, וממפים פרקים ורכיבים לתוצרים. הרשימה הנוכחית היא רשימת מועמדים.
3. מכריעים בצורך בחומרי הורים ומלווים נפרדים ובמדריכי מטפל נפרדים למודלים או גילים. מעדכנים כמויות לפני הקפאה, אם נדרש.
4. סוגרים את הכרעות הזכויות והתאמות הגיל, מתעדים החלטות וגרסה, ורק אז מקפיאים את המניפסט.
5. מפרטי התחומים הכלליים יכולים להמשיך בסקירה במקביל. הפקת חומרי הטיפול הייעודיים מתחילה לאחר ההכרעות הנוגעות להם.

בדיקה חוזרת: להריץ משורש המאגר `python docs/hebrew-series-stage0/audit.py`. הפקודה אינה משנה קבצים. `--write` מעדכן את הדוח בלבד ורק לאחר בדיקת הסיבה לכל שינוי בבסיס. אין להשתמש בו כדי לעקוף פערים או אישורים.
